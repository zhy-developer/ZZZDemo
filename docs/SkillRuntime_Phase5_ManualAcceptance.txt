Phase 5 人工验收清单（2026-10-12）

范围与准备
1. 本批只验收已批准的星见雅 Normal1～5 开发白名单。Normal6、Rush_ATK、Skill、FinishSkill
   未补齐配置；不要将拒绝这些入口判定为已实现技能失败，也不要把这些技能标为验收通过。
2. 客户端工程 D:/GitHub/ARPGDEMO，服务端工程 D:/GitHub/ZZZServer，Unity 2022.3.62f2c1。
   服务端地址沿用 NetGlobal/当前开发环境；自动验收用真实 TCP13001 和原 UDP 收发链路。
3. 保留正式场景/SO。手动用 Editor 时，在 BattleScene 的 GameManager 临时加 PilotMatchSettings，
   mode=DeterministicPilot，profile=MiyabiPhase4A_Development；完成后撤销这项临时场景设置。
   从 Assets/Scenes/LoginScene.unity 的登录和匹配流程进入 BattleScene，不直接在空 BattleScene 开始。
4. 本次 Builds/Phase5-Soak/PilotNetwork.exe 已在构建副本中启用上述开发模式，HP100/Hurt5000。
   双开时不要加 -phase5Client 参数（该参数会启动自动输入）；可用 -logFile 指定不同日志路径。
   Builds/Phase5-Network 是 HP20/Hurt100000 的同帧终局夹具，不能拿它判断正式攻击范围。
5. 使用两个真实客户端，或 Editor 加上述同配置开发构建；两端配置/规则摘要必须一致。
   不需要保存临时测试攻击盒，不解除 PartialPilot/BattleReady=false 的正式加载保护。

人工操作与预期（尚需用户确认，不因自动断言通过而自动勾选）
A. 入场、移动、连招
   两端原登录匹配进入同一局，确认左上 DEVELOPMENT 提示、HP100、同一配置。
   WASD 移动，鼠标左键普攻；连续按以覆盖 Normal1→2→3→4→5，换另一端重复。
   核对双方位置、HP、死亡、[PilotCast] 的 skill/cast/帧，不能出现攻击两次计伤或旧动画事件重复伤害。
   动画按逻辑帧采样及缺行走/跑步表现仍为 Phase4B 已知表现限制，不算本批已修复。
B. 终局、确认、返回
   分别完成槽位1胜、槽位2胜。死亡后不能再开始攻击；本地终局先成立，随后确认结果相同。
   两端 [RoundLocal]/[RoundConfirmed] 的 match、round、F、result、winner、hash 应一致。
   点“返回主界面（可重新匹配）”，重复点击不得重复清场。重新匹配应是新 match/session、HP恢复、旧攻击不再命中。
   Draw 难以人工同帧操作时，运行下方 Terminal 自动夹具；它使用真实结算但扩大测试 HurtBox，不代表正式玩法参数。
C. 缺帧及旧消息
   使用下方有界 UDP 代理验收，不通过暂停网络脚本或修改 HP 模拟。
   缺连续帧时允许等待；恢复后补齐，最终状态一致。不得跳过缺帧直接继续。
   首次结果上报/确认丢失后仍能确认、返回；新对局忽略旧 match 的迟到数据。
   关闭一端、只有单方报告、冲突报告时，当前约定是不擅自判胜负；断线裁决/恢复仍待产品决定。
D. 编辑器与资产
   Tools/Skill Editor（以工程现有菜单为准）打开技能编辑器，选 Normal1、Normal2。
   在隔离副本或自行备份的测试技能中拖动 slash_1，松鼠标后保存；Ctrl+Z / Ctrl+Y；关闭重开检查。
   右键删除、多选拖动、跨技能复制，核对 HitGroup 引用与新条目 ID；文本输入时 Delete 不删时间轴条目。
   Graph 拖节点只改布局；调整顺序后先预览，取消不改资产，明确应用后可 Undo/Redo。
   Inspector/Handles 双向调整 HitBox 和 VFX；Seek/循环两种模型，检查头身姿态、累计位移和粒子历史。
   音频试听音量、淡入淡出和听感；自动测试检查原生播放游标，不能替代人的听感判断。
   关闭预览、切技能、进入 Play、重载脚本后，不残留预览对象/声音，不修改原场景和 Prefab。
E. Legacy 与异常退出尾项
   不加 PilotMatchSettings 时做一次 Legacy 双端移动/普攻/闪避攻击回归。
   用户非正常关闭场景且结果尚未确认的 UI 操作体验、不同机器/公网网络、服务端进程重启恢复
   未被本机正常双端测试覆盖。不要据此声称已支持重连或自动裁决。

每次 RunName 必须新建，脚本拒绝覆盖既有运行证据。端口已有服务器时不抢占；先停止自己启动的服务器。
RunNetwork 启动/关闭它自己拥有的测试进程，日志位于 Logs/Phase5/<RunName>/。
客户端构建脚本会在 Assets 临时放置验收入口，finally 清理；不要在构建过程中操作工程资产。
主工程 Unity 会清理 Temp：先完成主工程构建/场景检查，再准备隔离编辑器工程。
隔离准备：pwsh -NoProfile -File Tests/Phase5/PrepareEditor.ps1。
隔离 Unity 执行入口及实际结果参见 Phase5 报告和 Logs/Phase5/Editor-*.log。

证据读取
- TraceComparison.json：实际消费输入优先，其次完整具名状态，首个差异保留前4帧上下文。
- AcceptanceVerification.json：实际终局、双方确认一次、服务端双方退役和时长/场数断言。
- A/B/*.jsonl：Match/Round/连续帧/阶段、配置、输入、具名权威状态；不得跨不同 match 对比。
- A/B/*.stats.json、Performance-A/B.csv、Measurements.json：逐场性能；分位数不能跨场简单平均。
- ProcessSamples.csv：外部 Windows 进程内存、句柄；客户端 Mono 的 private=0/handles=0 无效，不作零内存结论。
- 性能没有既定验收预算，目前提供 Development 基线；需另行确定目标设备、帧预算与允许 GC 指标。

本批验证结束后停在 Phase5，等待整体验收，不自动推进新玩法、正式配置或下一阶段。
