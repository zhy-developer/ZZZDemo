二、旧连招系统：代码和真实数据依据

1. Assets/Scripts/ScriptableObjectVO/ComboData/ComboContainerData.cs
   comboDatas 为有序 ComboData 引用列表；Init 缓存第0段；GetComboName 等按索引读取。
   SwitchDodgeATK 只用 DodgeATKData 替换第0段；ResetComboDatas 恢复缓存首段。
   SwitchBackDodgeATK 同样可替换第0段，但全 Assets/Scripts 搜索只有声明，没有调用。
   BackDodgeATKData 不代表当前战斗已接入的后闪专用分支。Graph只读显示该字段引用和明确诊断。

2. Assets/Scripts/Game/Fsm/Player/State Machine/Combo/CharacterComboBase.cs
   构造函数 CloneCombo 复制 lightCombo/heavyCombo 和列表，每角色运行时操作自己的副本，Init 缓存首段。
   TryGetAttackIndex：非闪避、同一容器且canLink=true时使用comboIndex；否则索引0。
   PlayNetworkAttack：消费发送端选定的索引，不用接收端动画时间重新选择；闪避替换0，否则恢复普通首段。
   UpdateComboAnimation：currentIndex赋值 → ATK状态 → CrossFadeInFixedTime(comboName,0.111f,0,0) → 对应旧RootMotion → UpdateComboInfo。
   UpdateComboInfo 索引加1，超过最后段回0。因此图显示顺序边及条件性的末段回0，不表示自动连播或无条件状态转场。
   CanInput / CanATK / DisConnectCombo 修改原输入、攻击和续连标志。

3. Assets/Scripts/Game/Fsm/Player/PlayerActionController.cs
   Prepare(rop1/rop6) 检查 CanBaseComboInput；轻攻击且 IsDodgeOrSprint 才设 dodge。
   TryGetAttackIndex 选定索引编码进 payload；canATK决定Ready或Wait。
   Execute 使用 payload 的索引和dodge调用 PlayNetworkAttack。
   重攻击、技能和终结技能走原有独立入口，Graph不把它们改造成任意分支。

4. Assets/Scripts/Game/Fsm/Player/State Machine/Movement/PlayerMovementStateMachine.cs
   IsDodgeOrSprint 同时包括 dashingState、dashBackingState、sprintingState。
   因此前闪、后闪和疾跑期间的轻攻击当前都经过 DodgeATKData，而不是后闪自动使用 BackDodgeATKData。

5. Assets/Scripts/Game/Fsm/Player/Player.cs
   PrepareNetworkAction / ApplyNetworkAction 连接网络动作控制器。
   EnablePreInput、CancelAttackColdTime、DisableLinkCombo 等 AnimationEvent 仅在有效攻击状态转发。
   Assets/Scripts/Game/Fsm/Player/State Machine/Combo/States/ComboStates/PlayerATKIngState.cs
   对应事件转发到 CharacterComboBase；Update检查动画攻击状态结束；StartMotion/Exit管理旧位移。
   Assets/Scripts/Game/Fsm/Player/State Machine/OnAnimationTranslation.cs 保留原状态回调。
   Graph不创建Animator Transition，不编辑AnimationEvent，也不认为每段必须自然播放到结束才能接下一段。

6. Assets/Scripts/Game/Input/PlayerNetworkInput.cs 与 Assets/Scripts/FrameSync/Battle/PlayerActionQueue.cs
   本地输入捕获 → PlayerActionBuffer.TryPrepareHead → Prepare选定payload；Wait缓存已选择段，待canATK允许发送。
   闪避清除尚未发送的攻击预输入。后续可靠队列与服务端回显保持原状。
   Graph没有接触这些代码、网络协议或帧调度。

7. 真实星见雅配置
   Assets/ScriptableObject/PlayerInfo/PlayerInfo（星见雅）.asset 的 lightCombo 引用
   Assets/ScriptableObject/ComboContainerData/星见雅基础连招.asset（GUID 6c9a63af5c7aae746b82775a2f40a128）；heavyCombo为空。
   列表为 Unagi_Normal_1 → 2 → 3 → 4 → 5 → 6，DodgeATKData=Unagi_Rush_ATK，BackDodgeATKData为空。
   对应资产位于 Assets/ScriptableObject/ComboData/星见雅/；AnimatorController为 Assets/Art/AnimatorController/星见雅.controller。
   Normal1/2显示 miyabi-normal-1 / miyabi-normal-2；其余旧技能显示 Legacy，不写入迁移字段。
   SkillID是显示身份，节点身份和正式连招引用仍是原 ComboData 对象/GUID，名称不是查找键。

允许编辑的关系：重排现有普通段；移除普通段后前后自动相接（至少一段）；替换已接入的Dodge入口。
不支持的关系：任意条件边、跳转规则、新运行时分支、BackDodge接入。删除中间段是改变整个列表，不是为玩家增加动态跳段能力。
为避免旧 SwitchDodgeATK 的空引用报错，已配置的Dodge入口不能直接清空，只能替换。原本为空的容器显示Warning，可补配置。

三、实现方式与安全

SkillComboGraphDraft 是编辑器内存事务，不是可序列化的第二份战斗配置。它只记录编辑基线、待应用列表和Dodge引用。
Apply前检查：持久化资产、非空列表、缺失引用、重复普通节点、非空动画入口、已登记节点的空/重复SkillID、删除Dodge、外部修改冲突、Play Mode。
完整差异包含原资产路径、修改前后列表、闪避引用、Legacy涉及情况、起手与索引影响；用户明确点击“应用到原资产”才写入。
使用 SkillEditCommands.Apply，在实际修改之前 RegisterCompleteObjectUndo；一次写入列表和Dodge，一次Undo/Redo；Flush保存原容器。
基线冲突时禁止覆盖，必须取消草稿/重载。取消、关窗、脚本重载和进入Play会丢弃未应用草稿；资产不受影响。
BackDodgeATKData不写，ComboData.skill不写，Animator/网络/RootMotion/战斗执行代码不写。
GraphLayout/GraphNode 仅保存在 Library/SkillEditor/Workspace.asset，按容器GUID、节点资产GUID索引，包含位置、缩放、平移。
布局待保存、关系草稿未应用/容器已保存、技能JSON待导出分别显示。保存布局或应用Graph不会自动导出JSON。
Phase1 DTO/Schema不含连招边；Graph明确提示关系不在技能JSON中。实际测试比较Graph应用前后Phase1 DTO不变。
Graph嵌在原SkillEditorWindow，通过页面工具栏切换；树和Graph共享owner；双击对应Timeline。
Legacy节点可选、定位原资产和查看，但不自动创建技能配置；进入Timeline显示未登记提示。
节点右键或普通连线右键启动重接，随后点击目标节点；它等价于列表重排。线条不代表新的条件分支。

六、Unity逐项人工验收

1. 打开 Tools/Skill Editor/Skill Editor，切换“连招 Graph”。核对所选容器为星见雅基础连招，六个普通节点及Rush节点，Normal1/2显示SkillID，其余Legacy。
2. 核对青色普通顺序、灰色条件回0、黄色闪避替换0和接第1段；Back明确无调用，不应当作生效分支。
3. 单击节点检查选中，双击Normal1/2进入对应Timeline；从技能树选Normal2，再回Graph应定位它。Legacy双击不得登记新技能。
4. 拖动节点、滚轮缩放、中键平移，保存布局，关闭窗口和重启Unity后复查。正式容器文件与JSON不应因此变化。
5. 推荐先复制一份容器作为测试资产，在Graph的ObjectField选择它。节点右键前移/后移；或右键节点/青色边选择重接，然后点目标。检查只产生关系草稿、原容器不变。
6. 点击预览变更，逐项核对路径、之前/之后、Dodge、Legacy、入口影响。选择取消，原资产不变，草稿可继续编辑；再“取消草稿/重载”彻底放弃。
7. 重做修改并明确应用：Inspector里容器引用正确；一次Undo/Redo恢复整个批次。保存后关闭窗口、重启Unity验证。
8. ObjectField替换Dodge为有效技能，或“闪避入口连线”点节点；必须经确认才写入。清空已有Dodge、删除最后普通段、空引用、重复ID应被拒绝。
9. 草稿未应用时用普通Inspector修改容器或Undo外部变化，Graph必须提示冲突且不能覆盖。取消/重载后才能继续。
10. 验证Graph应用前后技能JSON待导出状态按技能自身数据决定，不能把Graph关系标成已导出；点击Export仍使用原Phase1功能。
11. 回归Timeline多选、批量移动、Ctrl+C/V、跨技能HitGroup、Delete、文本输入保护、Undo/Redo；回归Scene预览Seek、Shapes、RootMotion与关闭清理。

八、已知限制与回退

- 不支持任意分支；BackDodge无实际调用，保持只读。若需要启用，须另行批准运行时工作，不能在2D-2补接。
- 不添加全新普通技能到序列，本批聚焦现有段重排/移除和Dodge替换；被移除草稿可取消恢复，已应用可Undo或通过原容器Inspector维护。
- 普通列表同资产重复出现可查看索引，但本版禁止应用有歧义的重复节点配置。
- Graph检查引用/身份/结构，不证明新顺序的动画手感或某任意新Dodge技能与角色Animator兼容。替换入口需人工确认原comboName在角色Controller存在，Graph不自动改Controller。
- 布局本机Library保存，不导出、不参与运行时；不承诺跨机器同步。未应用关系草稿不跨重载保存。
- 默认容器仅按已保存选择或目录技能引用交集查找，并非新增角色到容器的运行时绑定。顶部始终显示真实目标，其他角色可显式选择。
- 2C/2D-1未完成的正式战斗与完整人工矩阵仍为待办；未静默关闭。

本批未改正式容器内容，无资产迁移；若用户之后已明确应用关系编辑，应单独Undo或从自己的备份恢复该容器，不要整体reset仓库。
