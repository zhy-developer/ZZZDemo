# 技能运行时第二轮：双方地面战斗

本轮接入现有网络帧消费链，双方各一个角色，使用技能制作数据执行地面战斗。**尚未编译、运行 Unity 或执行任何测试，所有验证由用户人工完成。** 本文是实现说明和待验收清单，不是通过报告。

## 当前配置与范围

星见雅 PlayerSO 已绑定 `Assets/Resources/SkillConfigs/Unagi_CombatProfile.asset`，其中普通攻击绑定已有的 `Unagi_Normal_1_Skill`。两名网络玩家仍使用当前项目的星见雅预制体。

| 参数 | 当前值 |
| --- | --- |
| 双方生命 | 100 |
| 受击圆半径 | 4000 逻辑单位，即 0.4 Unity 单位 |
| 第一段普攻伤害 | 沿用 20 |
| 顿帧 | 暂时全局停用，资产原值保留但不生效 |
| 受击硬直 | 按用户确认改为 8 帧，不含顿帧 |
| 普通移动距离 | 每帧 3000，即 0.3 Unity 单位，对应原 30 × 100 |

用户已经摆好的攻击区域、帧区间及确认标记保留。生命、受击圆、移动速度和动作绑定在对战配置中编辑，伤害和时间仍在技能命中组中编辑。

当前只绑定普通攻击。技能、大招、闪避如果未在对战配置中绑定新技能资产，收到输入后会确认并忽略，不调用旧 Animator 战斗。第三轮已接入预输入、连段以及特效音效事件，详见 [第三轮实现与人工验收](skill-runtime-round-three.md)。霸体、无敌、格挡、击退和角色切换尚未接入。`MoveCancel` 用于中途恢复普通移动。

## 每帧顺序与时间含义

网络帧为唯一战斗时钟，间隔 33ms：

1. 按帧开始时的硬直计数判断是否可行动，推进已有技能的边界；顿帧计数清零。
2. 应用按 battleID、operationID 排序的网络输入。
3. 全员应用整数位移并限制在地图边界。
4. 用所有角色移动完成后的 XZ 快照收集全部命中。
5. 统一扣血，再统一打断受击角色并转入受击或死亡状态，不施加顿帧。
6. 同步模型、动画和生命显示。

新释放首先在 **F0** 显示初始姿势、检查第 0 帧区域，不消费位移。之后每个可推进帧消费 `[F-1,F)` 位移，到达边界 F 后用 `startFrame <= F < endFrame` 检查区域。无打断、无地图边界裁剪、无移动取消时，朝向 +Z 的技能 F 与编辑器游标 F 的位移和姿势对应。

到 `totalFrames` 边界消费最后一条位移，旧技能结束，不再检测其区域；这一帧可接受新技能，但不会叠加普通移动。新技能方向不会改变上一技能最后一条已算出的位移方向。边界处显示已切换到空闲或新技能的姿势。

有移动输入且技能当前帧在 `MoveCancel` 区间时，放弃当前步及剩余技能位移，关闭区域并执行普通移动。要完整观察样例到末尾，应在攻击时松开移动键。

### 命中与受击

- 角色受击体为逻辑根节点上的圆，攻击区域为圆或绕 Y 旋转的矩形，只检测 XZ。区域随逻辑朝向旋转，边界接触算命中。矩形边和角点都检测。
- 同次释放、同命中组、同目标只结算一次。不同组独立结算，新释放重新记录。
- 普通受击立即取消技能及剩余攻击区域、位移。候选命中已经收集完成，因此双方同帧成立的命中都结算，包括双方被打断或同时死亡。
- 顿帧暂时全局停用：命中不暂停攻击者技能、动作、位移或显示平滑；受击者立即转入正常播放的受击动作。hitStopFrames 配置保留，当前不施加。
- 受击硬直仍为完整 8 帧，命中后下一逻辑帧开始递减；减到 0 的那帧仍不可行动，下一帧恢复。
- 同时收到多个硬直取最大值，不相加，新命中不会缩短原有硬直。顿帧日志字段保留，当前应始终为 stop=0、frozen=false。
- 生命归零后本局停止战斗行为，网络帧与输入确认仍继续。界面显示胜者，双方同帧归零显示平局。退出继续使用现有流程，本轮未新增结算协议或自动重开。

## 脚本职责和隔离

以下脚本路径相对 `Assets/Scripts`：

| 文件 | 职责 |
| --- | --- |
| `SkillData/SkillCombatProfile.cs` | 角色对战数值、指令绑定、基础动画 |
| `SkillRuntime/CombatSkillLibrary.cs` | 开局配置副本、准入校验、累计位移缓存 |
| `SkillRuntime/CombatFighter.cs` | 每名角色的独立状态和命中记录 |
| `SkillRuntime/CombatMath.cs` | 固定整数方向表、旋转和移动 |
| `SkillRuntime/CombatCollision.cs` | 整数 XZ 几何判定 |
| `SkillRuntime/CombatWorld.cs` | 全员帧调度、命中收集与统一结算、胜负判断 |
| `SkillRuntime/FrameCombatSession.cs` | 网络去重确认、场景角色与战斗世界的连接 |
| `SkillRuntime/CombatAnimationView.cs` | 接收表现状态，按渲染帧播放动画、混合和冻结 |
| `SkillRuntime/CombatPresentationClock.cs` | 连续动画时钟与逻辑时间锚点的渐进校准 |
| `SkillRuntime/CombatLocomotionView.cs` | 旧移动 FSM 到 AnimatorControllerPlayable 的表现适配 |
| `SkillRuntime/CombatStatusView.cs` | 人工验收面板及可选逐帧日志 |

`BattleManager` 每次消费网络帧只调用一次 `RoleManager.Logic_Step`，不再另行执行旧 RoleBase 移动。RoleBase 接收整数位置并显示结果，网络 Player 只采集输入、保留相机绑定。旧移动 FSM 保留为表现层，旧连招 FSM 不参与新战斗。动画事件禁用，旧 ATK、旧状态回调和原生根位移不能重复触发战斗。旧 ComboData 及 Imported Events 不决定新对战执行。

网络动画接管时，将预制体原有的 Animator Controller 放入同一个手动 PlayableGraph，通过 AnimatorControllerPlayable 保留其状态、BlendTree 和过渡。Animator 组件上的直接 Controller 引用暂时置空以避免双重推进，退出接管时恢复，预制体资产不变。

自由行动时，旧 PlayerMovementStateMachine 的表现入口读取 `CombatFighter.Moving`，复用 Idle / Walking / Running 状态、WalkStart 起步和 Movement / HasInput 参数。默认沿用 Running 状态参数；本轮没有新增走跑切换输入或冲刺规则。表现入口不执行旧 FSM 的 Update、闪避位移或动画结束回调；旧 FSM 的动画写入通过 IMovementAnimationOutput 转发给控制器 Playable，不允许动画状态决定战斗准入、技能结束或位移。

技能逻辑帧仅作为技能动画的时间校准点，实际动画每个渲染帧连续采样。受击片段只在新受击时从头启动，之后由 AnimationClipPlayable 以速度 1 随渲染 deltaTime 自然播放，不读取 PoseFrame、不按收包调速，也不逐渲染帧重新 SetTime。进入技能采用技能中的 `blendInSeconds` 从移动控制器淡入，受击立即覆盖，连续技能直接切换，恢复自由行动时用 0.14 秒从最后技能/受击姿势淡回移动控制器。移动控制器在技能期间暂停，返回时重新选择待机或起步。淡入只影响姿势权重，不推迟技能 F0、攻击区域或位移；淡入期间画面是混合姿势，与编辑器单 Clip 预览存在预期差异。

逻辑/表现边界：SyncState 只接收动作、移动状态、技能时间锚点、新受击序号及结束通知，不调用 Graph.Evaluate。RoleBase.LateUpdate 调用 Render(Time.deltaTime)，移动 Animator、Movement 参数阻尼、技能/受击播放、混合权重均按渲染帧推进。删除上一版“每 33ms 采样骨骼、再插值相邻姿势”的方案，不再人为增加一帧动画显示延迟。

CombatPresentationClock 仅用于技能：新技能定位到逻辑时间，之后累计渲染 deltaTime。同一技能的新网络帧只更新校准点，时钟以最多正负 20% 的调速渐进跟踪时间差，不按收包重置、硬跳帧或倒放。受击已移除此调速校准。SkillFrameSampler.SampleAnimationAtTime 接收连续秒数，沿用技能动画的开始帧、裁剪范围和速度。片段播放到尾不会自行结束技能或解除受击，状态切换完全等待逻辑通知。

世界位置和朝向已按用户要求恢复原来的阻尼追赶：RoleBase.Update 使用 Vector3.SmoothDamp 更新角色根节点显示位置，使用 Mathf.SmoothDampAngle 更新 Modle 的 Y 朝向。每个网络帧只更新最新目标，普通更新不会重置当前显示位置或平滑速度，也不再按 33ms 重启位置插值。沿用 Inspector 的 positionSmoothTime（默认 0.08 秒）和 rotationSmoothTime（默认 0.1 秒）。Combat.Position / Shape 仍立即更新为逻辑坐标，战斗判定不读取平滑后的 Transform。

表现独立于逻辑帧播放，并响应新命中打断和对局结束。顿帧已暂时关闭，CombatAnimationView 和 RoleBase 不再根据顿帧字段暂停动画、混合、位置或朝向。旧 CameraHitFeel.PF 也改为空入口，移除暂停协程，不再暂停 Animator 或 VFX。死亡和对局结束仍保持最终显示。网络断流时待机/移动循环继续播放，技能/受击最多播放到末尾保持，位置只追赶最后目标，战斗逻辑不随表现推进。网络断流的提示与暂停策略后续再做。

本轮同时核对了现有表现入口：StateBarUI 的绿色血条在生命变化时接收数值，红条缓动在 Update 使用 Time.deltaTime；相机缩放也在 Update 使用 Time.deltaTime，没有改为逻辑帧更新。CombatStatusView 的逐帧日志记录逻辑事实，保留 OnLogicFrame；其 HUD 和 Gizmos 不推进战斗。新战斗尚未接入特效音效和旧 CameraHitFeel，不启用旧动画事件。后续表现遵循同一边界：逻辑发出事件和状态，表现自行播放，不能把播放循环放进 Logic_Step。

对战配置中旧 idleClip / moveClip 字段隐藏并保留序列化数据，不再参与运行或准入校验。

动作准入不使用本地动画进度：本地发送按钮意图和朝向，双方在收到同一逻辑帧后判断是否允许动作。技能中、受击中被拒绝的操作也确认序号，避免重传在恢复后补放。同一 operationID 只执行一次。没有新移动输入时保留上次方向。

配置开局时复制，Play 中修改源资产不会中途改变战斗，需重新开局。硬直 -1、已启用且未确认的攻击区域、空技能、重复指令、必要基础动画缺失、无效根位移等会阻止初始化并显示原因。未绑定音特效警告暂不阻止开局。

固定方向表精度为 1000000；坐标精度仍为 10000。旋转顶点量化为整数，矩形奇数尺寸的半长向零取整，误差小于一个逻辑单位。圆到线段的距离比较用大整数交叉相乘，避免浮点开方和整数平方溢出，不调用 Physics。

受击动画直接绑定星见雅当前控制器使用的正面受击片段；旧命中组的 `Hit_shake` 等名称不参与本轮查找。受击结束由逻辑硬直决定：动画较长会截断，较短保持末姿势。死亡暂保持受击初始姿势，由胜负文字说明结果，独立死亡表现后续补齐。

## 人工验收顺序

1. **编译与绑定**：由用户打开 Unity 检查 Console。确认星见雅 PlayerSO 的 `frameCombat` 绑定新配置，普通攻击及受击动画引用有效，角色预制体 Animator 仍绑定原控制器（第 0 层需有 Idle、WalkStart 状态及 HasInput、Movement 参数）。双方必须使用相同代码和资产；当前没有配置版本握手。
2. **进入对局**：沿用现有服务器和双客户端流程，确认双方 HP 100、逻辑帧持续递增、初始朝向相对，移动只改变 XZ。
   持续移动时双方应经 WalkStart 进入原控制器的 Locomotion，松开后经原过渡返回 Idle；释放普攻后恢复移动应重新进入起步动作。检查待机出招、移动出招、技能中途移动取消和受击恢复四类切换。网络角色 Animator 的直接 Controller 在接管期间为空是预期行为，原控制器在 PlayableGraph 内运行。再按第 5 项确认命中后没有顿帧。
   在 Unity Scene 打开 Gizmos，可见青色受击圆与橙色生效攻击区域。调试线来自实际整数几何，仅用于观察，不参与结算。
3. **单次命中**：靠近后松开移动键普攻，目标 HP 应从 100 变为 80；持续覆盖不能重复扣血。技能结束后新一次释放可以再造成 20 伤害。
4. **多个区域**：人工配置两个重叠且同组区域，重新开局后仍应只扣一次；换成不同命中组后检查各组独立结算。
5. **顿帧停用与硬直**：重新进入对局，开启 CombatStatusView.logEveryFrame。命中前后应始终 stop=0、frozen=false；攻击者技能连续推进，受击动画立即正常播放，并保持 8 帧硬直。HUD 显示“顿帧已停用”。即使命中组保留非零顿帧配置，也不应发生暂停。
   同一次受击不能因网络帧更新重启或变速；新的命中可以重启受击。短于硬直的动画播完后保持末姿势，长于硬直的动画在逻辑恢复时淡出。此次不改变伤害、同帧命中结算、受击打断或硬直参数。
6. **打断**：让一方先命中另一方正在执行的技能，检查受击者立即清空技能，后续不再有攻击区域或根位移，硬直结束才可重新出招。
7. **同帧对攻**：双方相向同帧进入有效区域，日志应出现 `hits=2`，双方各扣 20，不能因 battleID 顺序吞掉一方的命中。同帧双方最后 20 HP 被打掉时应平局。
8. **编辑器对照**：无命中、无移动输入、远离边界，朝向 +Z 释放；对照日志 F7 等帧的逻辑位置与 Scene 游标 F7。运行时模型位置有阻尼跟随滞后，动画按连续显示时间播放且存在混合，不能把同一时刻的模型截图当作 F7 精确采样结果。最终位移只消费一次；移动取消区间内按移动应结束技能和剩余位移。
9. **双端一致**：分别开启逐帧日志，按相同 `frame=` 比较 `hash=`、HP、位置、技能帧、顿帧与硬直。改变窗口渲染帧率后仍应一致，不要比较不同逻辑帧的 HUD。摘要只用于人工诊断，不是防作弊或配置版本验证。
10. **旧事件隔离**：确认没有旧 ATK 距离伤害或旧根位移叠加。当前无音特效、完整连段，且未绑定的技能/大招/闪避无效果，属于本轮范围。
11. **错误与清理**：把硬直改为 -1 或区域改成未确认后重新开局，应在 HUD/Console 看到初始化错误。恢复配置后重进；退出场景和停止 Play 应释放 PlayableGraph 与配置副本。

12. **显示平滑**：在 60Hz 或更高帧率观察持续移动、转向、起步/停止、普攻和受击。位置/转向沿用 SmoothDamp，Inspector 的平滑时间生效。动画和混合在每个渲染帧持续变化，命中不再施加暂停；对局结束保持最终显示。短暂停止收逻辑帧时，动画可以继续播放，HP/命中/技能逻辑帧不能自行推进。调试区域仍显示逻辑坐标，可与平滑模型有偏差。

战斗逻辑仍为每 33ms 一帧；世界位置和朝向采用原 SmoothDamp，动画播放、参数阻尼和过渡使用渲染 deltaTime。逻辑只控制状态、准入、命中、技能结束；顿帧暂时全局停用。闪避、冲刺掉头、切人等尚无新逻辑支持的状态不接回网络战斗。本轮没有改服务器协议、传输或补帧机制，也没有运行任何双端验收。
