二、主要接口与调用示例

1. RuntimeSkillCatalog.TryCreateIsolated(snapshot, frameIntervalMs, precision, out catalog, out error)
   输入现有 SkillConfigSnapshot；重新使用现有 Schema Validator；通过 CopyData 获取独立副本。
   构建不可变 RuntimeSkill / RuntimeSegment / RuntimeGroup / AttackShape / RuntimeEvent 索引。
   所有暴露集合为只读包装，成员只有 getter 或 readonly 值；不保留可变 DTO 对象引用。
   Groups 仅投影资格所需的 ID/Single/Repeat/Interval；未将伤害等后续规则另设默认值。
   RuntimeSkill.Group/SegmentAt/目录 Skill 用于稳定索引；Animation 顺序沿用原已验证连续列表。
   错误形状给出 SkillID/HitBoxID；单位不匹配、超几何范围明确拒绝。
   正式就绪始终 false；ISOLATED_ONLY、PARTIAL_CATALOG、HURTBOX_REQUIRED 明确报告。
   需要重映射的 Root Motion 报运行能力缺口；缺少来源元数据保持 Warning。
   旧 Loader(requireBattleReady:true) 完全未改，仍拒绝完整战斗加载。
   读取索引不等于验证真实 Animator/Prefab；Resources 验证仍由旧 Loader.TryLoad 负责。

2. 生命周期调用顺序（测试适配，不是生产帧循环）：
   world.TryBeginFrame(F) == Started
     -> 对已确认接受的动作调用 StartAccepted(entity, runtimeSkill)
     -> 外部完成模拟/真实逻辑移动（本批仅测试数据）
     -> CapturePostMove(双方 EntityGeometrySnapshot)
     -> 读取 Candidates/Events
     -> CanAccept(candidate)（任意次数，只读）
     -> 外部策略拒绝：不调用提交
     -> 外部策略接纳：TryCommitAccepted(candidate)
     -> CompleteFrame()
   必须检查 TryBeginFrame 返回值；Duplicate/Gap/PreviousFrameOpen 都不能重派输入。
   Candidates 是几何及同组去重结果，不自动等于伤害，不自动消耗命中记录。
   Events 只是有归属、排序的事件描述，没有执行委托；读取集合不执行任何事件。
   正式世界未来仍由现有网络帧入口驱动；本批没有安装调用者。

3. EntityKey = Session + Round + BattleId + Generation。
   Session 是宿主显式提供的共同对局上下文，不误用本地 BattleData.battleID。
   Generation 区分同槽位新生命；CharacterID/SkillID 是配置身份，不是实体身份。
   CastKey = EntityKey + 单实体递增的 long Sequence。
   只有 StartAccepted 才递增；空操作、查询、采样、缺帧不会递增。
   RuntimeSkillCatalog 的 CharacterID/SkillID 留在 CastFrame.Skill；候选保留 SkillID。
   同角色镜像/相同序号通过 EntityKey 区分；同技能重复施放通过 Sequence 区分。
   Session/序号不能回绕。该类不实现断线快照恢复；重建同一对局不能靠任意归零序号恢复。

4. 退出/资源所有权
   StartAccepted 替换旧施放时，仅清理旧 CastKey 记录与 handle。
   OwnHandle/OwnsHandle 使用不透明测试句柄；不启动或停止真实 Root Motion/特效。
   Exit(oldCast, reason) 在旧施放已替换时返回 false，不影响新施放。
   采样前退出即时发生；采样后退出延迟至 CompleteFrame，不能撤销共同快照的候选。
   不同退出原因同时请求会抛出明确冲突，要求后续解析器先决策；本批不选择死亡/打断优先级。
   Exits 报告释放句柄；调用方负责未来真实资源释放，本批没有隐式回调。
   Dispose 幂等清理会话全部施放/记录/handle；关闭后不允许推进。

三、已经落地的时间契约

宿主传入的帧间隔须匹配导出 DTO；本工程当前 NetConfig.frameTime=33ms，精度10000。
不采用1/30秒，不在几何或施放推进中读 Time.deltaTime。
SchemaVersion=1 的原校验规则继续限制33ms/10000；本批没有改写该规则。
long 网络帧必须从宿主声明的 lastCompletedFrame+1 连续交付；默认首帧为1。
正整数帧缺口返回 Gap；已消费帧或当前重复帧返回 Duplicate；状态不改变。
连续空操作帧正常 Begin/Capture/Complete，因此已活动施放正常推进。

D 取已经校验的 SkillDto.durationFrames，必须等于最后一个 AnimationDto.endFrame。
首 Clip 从0开始，相邻 Clip 不允许空档或重叠；校验失败不构建索引。
StartAccepted 所在帧 skillFrame=0；之后 skillFrame=F-StartFrame。
窗口和 Clip 均按 [StartFrame,EndFrame)；0..D-1 有效。
Capture 使用宿主提供的本帧移动后快照，不内部移动、不缓存渲染 Transform。
D-1 完成候选资格和接纳提交后，在 CompleteFrame 正常退出。
最后帧 Committed 输出保留到下一帧 Begin，退出清账不丢失已提交结果。
跨 Clip 仅 SegmentAt 改变，不换 CastKey、不清组记录。
Clip/Animator视觉结束、位移覆盖结束不控制本模块退出。外部确认的提前退出通过 Exit/替换表达。
长帧编号和施放序号使用 checked/显式边界，不环绕。

四、数值与形状契约（本批实现，不是 Q32.32 名称假设）

输入：
- 坐标仍是10000逻辑单位/Unity单位；LogicPose.X/Z 与 shape/hurt 的本地 offset X/Z 同单位。
- 根X/Z、本地offset X/Z 的合法范围为[-1,000,000,000, +1,000,000,000]，即正负100000世界单位。
- 有效平面尺寸/半径为[1, 1,000,000,000]。
- 该运行能力范围通过构建/构造检查；超范围抛 ArgumentOutOfRangeException，目录构建转为错误。
- 不是将超范围值钳制回地图，也不是溢出后再转换。实际地图约束仍留在原系统。
- 根Y、受击offsetY作为long保留；HitBox.offset.y仍为原int。它们不进入检测计算或距离过滤。
- 原作者数据的 Box 高度、Capsule 总高度合法性继续检查，但不据此比较双方垂直位置。
- 角度输入为int毫度，支持负值/多圈；内部先扩到long再倍乘与规范化。

方向/偏移顺序：
- LogicPose.FacingMilliDegrees 沿现有roleDirection约定：0朝世界+X，90000朝+Z。
- 角色正Y yaw = 90000 - FacingMilliDegrees；形状自身正Y yaw 独立采用 yawMilliDegrees。
- R(yaw)作用为 (x,z) -> (cos*x + sin*z, -sin*x + cos*z)。
- 攻击中心 = 根XZ + R(角色yaw)*本地offsetXZ。
- 攻击朝向 = R(角色yaw)*R(形状yaw)。形状自身yaw绝不再次旋转本地offset。
- 受击圆心 = 目标根XZ + R(目标yaw)*Hurt offsetXZ；圆半径不随方向缩放。
- 仅给新几何传确定性逻辑角度，不读模型朝向。旧RootMotion方向表精度100及截断完全未修改。

确定性角度构造：
- 输入刻度为半毫度，完整一圈720000；因此奇数毫度的扇形半角无需截断。
- 象限先规约到[0,90度)，再以固定Q96整数计算sin/cos的24次Taylor递推。
- Pi常量来自固定十进制前缀314159265358979323846264338327950288419716939937510/10^50，
  乘2^96后向下截断。常量解析使用InvariantCulture。运行时不用Math.Sin/Cos/Atan2。
- 源弧度 x=PiQ96*halfMilliRemainder/360000（正数截断）。x*x/2^96截断。
- 每个Taylor递推的大整数除法向零截断；次数固定，不按浮点收敛判断。
- t=tan(theta/2)从sin/(1+cos)估计，量化到Q48：最近舍入，正半值远离零。
- 令q=2^48、p=量化t：c=(q^2-p^2)/(q^2+p^2)，s=2pq/(q^2+p^2)。
  这是精确有理数，c^2+s^2严格等于1，避免“近似单位向量”造成隐性缩放。
- 象限恢复用交换与符号；0/90/180/270度严格精确。360度边界规范化回0。
- 两个旋转用有理数矩阵复合，不把复合结果再量化一次。
- 角度构造之外，偏移、半尺寸、变换、距离、点积/叉积和比较全部为精确有理数，不取整。

范围/精度说明：
- Q96递推在x<pi/2下，截断尾项极小；每次定点截断小于一个Q96单位，有限24步。
  保守用10000个Q96单位覆盖中间量化误差，远小于最终Q48量化的一半步。
- Q48量化对应单旋转角度误差小于约4e-15弧度；轴向角无误差。
  这是与理想连续角度的差异，契约边界始终按上述有理数旋转定义。
- 本输入范围下，可以用0.001逻辑单位作为角度近似引起的位置偏差的保守量级上界；
  不把它加到半径上，不用epsilon把未相交强行变成命中。极近理想边界可能与理想实数角度不同。
- |旋转offset的单轴分量|<=sqrt(2)*1e9；中心单轴绝对值<2.415e9。
- 加半径/矩形半对角后，形状范围单轴绝对值<3.415e9；不将这些中间量写回int。
- 双方中心单轴差可达4.829e9，平方距离可超过Int64；旋转有理数分母本身也可达97位。
  因此不是“换成long就足够”：BigInteger用于分子/分母和所有乘积，先扩位再算。
- 分数每次以GCD约分、保持分母正数；没有浮点、无随机数、无平台三角函数。
- 计算树、Taylor步数固定，输入范围受限；没有可由输入无限延长的迭代。
- 奇数完整宽深以精确 value/2 分数保留，例如13005/2=6502.5，不提前截断。
- Sector半角以半毫度构建；90.001度的完整角保留45.0005度的半角。

五类形状：
- Sphere、当前竖直Capsule、竖直Cylinder：平面圆。
- Capsule仍要求原三维height>=2r，height=2r合法；没有引入横向轴字段。
- Box：有向矩形。转换目标圆心到盒局部坐标，clamp最近点，用完整受击半径比较。
- Sector：在角域内检查扩大的径向范围；在角域外检查两条有限侧边的最近点。
  有限线段距离同时覆盖原点和端点；角域内覆盖内部和圆弧。
  <=180度采用两边条件交集，>180度采用并集；360度专门按完整圆处理。
- 相切统一<=，不只检查目标中心，不用PhysX。
- 首版是每帧离散快照检测；高速跨过目标可能漏检，未实现扫掠或连续碰撞。

五、记录、排序与不在本批固化的规则

记录键：(CastKey, HitGroupID, TargetEntityKey)，组规则来自冻结的RuntimeGroup。
候选收集与资格查询不写账；外部拒绝时不调用 TryCommitAccepted 即可。
Single在本次施放有效提交一次；Repeat从上一次提交网络帧T算，T+N可再次提交。
同帧第二次提交返回false；新帧不能提交旧帧的candidate；另一个world产生的对象也不是本帧候选。
这不是Damage>0、HitStun>0或无敌判定。本批不决定零伤害是否应被外部接纳。
同组多个实际相交盒按HitBoxID的Ordinal最小值选代表，不取未相交的最小ID。
现有Validator保证技能内条目ID唯一、组引用有效；无效配置不产生索引。
候选排序为Frame、CastKey(EntityKey/Sequence)、GroupID(Ordinal)、TargetEntityKey、代表HitBoxID。
技能内事件排序为Frame、Order、ItemID(Ordinal)；同帧全局输出先区分实体/施放，再Order/ItemID。
DescribeState显式稳定排序序号、活动施放、命中账本、资源所有权、候选、事件与提交结果；
不使用Dictionary枚举顺序或GetHashCode作为摘要。宿主未来需另加入位置、配置版本和HP等自有状态。
