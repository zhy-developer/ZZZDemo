技能编辑器与正常战斗使用说明
日期：2026-10-12。客户端 D:/GitHub/ARPGDEMO；服务端 D:/GitHub/ZZZServer。
最终证据与版本范围见 SkillRuntime_FinalDelivery.txt；Phase 5 已由用户验收，本轮属于 Phase 4 集成收口。

1. 当前默认范围与配置

默认场景链：Assets/Scenes/LoginScene.unity -> MainScene.unity -> BattleScene.unity -> ClearScene -> MainScene。
ProjectSettings/EditorBuildSettings.asset 已包含上述四个场景，普通 Build 使用保存的 BattleScene。
BattleScene 内 GameManager 组件实际位于 Main Camera 对象；同对象上的 PilotMatchSettings：
  mode=DeterministicPilot
  profile=Assets/ScriptableObject/SkillConfigs/Miyabi_NormalGameplay.asset
这是保存的正常入口，不需要 Prepare Arena、测试场景、测试命令或运行时改开关。
历史 Pilot 名称保留，不表示只能在测试中使用。

本轮用户允许先假定可细调的数值和范围；声明初始范围：
  星见雅镜像1v1，WASD移动，鼠标左键普攻Normal1～5、预输入与连招；受击、死亡、胜负/Draw确认；退出后重新匹配。
  初始HP100，HurtBox圆半径5000逻辑单位=0.5世界单位，XZ偏移0。
  创作HurtBox仍是竖直Capsule，height=10000；所有几何命中只看XZ，保留Y字段和既有移动用途。
  HP在运行Profile的Initial HP设置（旧序列化字段testHP），不复制到技能JSON。
  正常模式HurtBox只读取角色目录/导出JSON；Profile的旧testHurtRadius/testHurtOffset仅供开发夹具，正常模式不使用。
  Normal6、Dash/闪避攻击Rush_ATK、Skill、FinishSkill未开放；不猜FinishSkill=Ultimate。
  原六段连招容器未删改。Normal5窗口内请求未迁移Normal6会拒绝；Normal5正常结束后再次按普攻从Normal1开始。
  不是新增五段自动循环，也不宣称全部历史动作迁移完成。HUD明确显示未开放内容。
  Shift/闪避/技能键不能使未迁移动作回退旧伤害链；新模式不把这些未开放动作加入本地队列。

目录仍标记PartialPilot，保留作者自建测试技能。SkillConfigSnapshot/RuntimeSkillCatalog.BattleReady仍false，
requireBattleReady=true仍拒绝把整个目录作为完整角色配置。正常宿主根据显式allowedCombos逐项检查：
  连招连续前缀/唯一引用、源/JSON摘要、Resources实际资源、动画状态、Clip和RootMotion时间映射、
  明确HurtBox、HP范围、门控事件、已支持事件与表现能力；实际绑定角色前检查状态和骨骼。
全部通过才打印[GameplayReady] scopeReady=true wholeCatalogReady=false并进入双方Ready握手。
该“范围内就绪”不等于整个角色目录已完整迁移；未来扩大范围必须补数据和对应输入/运行适配，不能仅添加引用。

2. 启动服务器和两个客户端

Unity版本：2022.3.62f2c1。两端必须使用本次对应版本与同一配置摘要。
服务端编辑器：打开D:/GitHub/ZZZServer，打开Assets/Scenes/LogScene.unity，进入Play，点击启动服务器。
启动界面默认2人；其他人数明确拒绝。旧PlayerPrefs存过1人不会继续覆盖默认1v1人数。
也可运行D:/GitHub/ZZZServer/Builds/FinalDelivery-Release/ZZZServer.exe，在界面点击启动。
服务端界面显示实际绑定IP。TCP端口13001，UDP端口由登录响应提供。

客户端地址在Assets/Scripts/Config/Net/NetConfig.cs的ServerIP（当前192.168.1.5）。
若服务器IP不同，先改此地址并重新构建两端客户端；没有自动发现，也没有新增网络地址配置体系。
确认系统防火墙允许对应TCP和UDP。不要仅检测TCP可达便声称完整联调通过。

客户端编辑器：打开LoginScene进入Play；或运行Builds/FinalDelivery-Release/ARPGDEMO.exe。
启动第二个同版本客户端，分别点登录，再点主界面的匹配。每个进程拥有独立登录身份，可同机运行。
不直接从BattleScene按Play，它需要登录/匹配返回的match、session、slot和票据。
主界面默认星见雅；练习按钮当前没有实现，不是本次默认对局入口。
WASD移动；鼠标左键普攻，窗口内继续按键衔接Normal2～5。静止普攻瞄准本局对手逻辑位置；移动输入方向优先。
结算面板先显示本地终局等待确认，服务端确认后显示Winner或Draw，点击“返回主界面（可重新匹配）”。
再次匹配产生新match/session。当前每match只有round=1；没有BO3、自动下一局、积分或断线判负。

Development Build用于日志和诊断；normalGameplay配置允许非Development普通构建。
发布构建仍使用相同保存场景与能力检查。不要把MiyabiPhase4A_Development测试Profile用于非Development构建。
复制程序时保留整个构建目录（exe、*_Data、UnityPlayer.dll等），不要只复制exe。

3. 判断当前模式与诊断

查看客户端日志：
  [GameplayReady]：当前支持列表、HP、Hurt半径、规则和范围内就绪。
  [PilotMatch]：mode=DeterministicPilot、rules=phase3c-v1/pilot4b-v1、digest与实体身份。
  [ProfileSealed]：编辑器更新摘要后的配置digest；新对局使用的新快照。
  [MatchRejected]：双方模式/规则/配置/协议不兼容，不会静默退回Legacy。
  [PilotHalt]：权威运行故障，保留日志，重新初始化对局，不切换旧伤害链。
  [PilotReject]：不支持动作、窗口未开或下一段超出开放范围。
  [PilotPresentation]：资源/绑定问题；表现失败不改权威结算。
  [RoundLocal] -> [RoundConfirmed] -> [RoundRetired]：本地终局、业务确认、离场。
服务端查看监听成功、[RoundServer]、[FrameReplay]、[ServerStartRejected]。
结果异常/双方摘要不一致时保留现场，不擅自判胜负或Draw；15秒等待提示不是业务超时判负规则。
Unity Editor日志在%LOCALAPPDATA%/Unity/Editor/Editor.log；普通程序按Unity标准Player.log保存，
同机双开需要分开日志时可给各进程-logFile绝对路径，不影响玩法配置。

4. 技能编辑、保存、导出、运行

菜单 Tools > Skill Editor > Skill Editor。
选择Assets/ScriptableObject/SkillConfigs/MiyabiPhase1.asset，名称保留；唯一技能创作源仍为ComboData.skill。
原技能：Assets/ScriptableObject/ComboData/星见雅/Unagi_Normal_1.asset～Unagi_Normal_5.asset。
在Timeline/Inspector编辑Animation、HitBox/HitGroup、无敌、可打断、事件、VFX/SFX；Scene View负责安全预览与空间编辑。
全部时间使用33ms整数逻辑帧，[StartFrame,EndFrame)；Trim/PlaybackSpeed按既有映射，不自动缩放其他事件。
纯预览倍速不修改技能配置。Root Motion源数据仍为旧JSON，不因几何忽略Y删除其Y字段。
当前连招运行必需combo.preinput、combo.attack-ready、combo.move-interrupt，combo.link可在正常结束时隐式关闭；
不能删除必需门控后靠旧AnimationEvent补偿，Profile会拒绝不支持的门控序列。

修改后：
  1) 保存SO（自动保存或Save SO），Validate；修复Error，审阅Warning及适用范围。
  2) 明确点击Export JSON。输出Assets/Resources/SkillConfigs/Character_miyabi_Skills.json。
     自动保存不自动导出；Error不覆盖旧JSON；Warning允许导出但不是运行就绪证明。
  3) 在Project选择Miyabi_NormalGameplay.asset，点击Inspector“校验已导出的配置并更新摘要”，
     或Tools > Skill Runtime > Validate and Seal Selected Profile。
     此操作检查导出是否最新，先在临时副本验证能力，再登记Undo并只保存新摘要；失败保留原摘要。
     不迁移技能、不生成门控、不修改伤害/范围、不隐式导出。支持Undo/Redo。
  4) 退出当前对局，重新登录匹配/重新匹配。运行配置按对局冻结，不热替换正在施放的Cast。
     修改资产后，独立exe须重新构建；编辑器改SO不会自动更新已打包程序。双方使用同一构建/摘要。
  5) 从LoginScene正常入口验证目标动作、位置、血量、结果；核对双方[PilotMatch]摘要。

基础伤害在原ComboData.comboDamage；使用基础伤害的HitGroup直接引用它，不另抄一份。
HurtBox在角色目录中改，重新保存/导出/更新Profile摘要。HP在Profile改，更新摘要；不需要为了HP修改技能JSON。
连招Graph实际修改原ComboContainerData，仍需“预览变化->应用”，支持Undo。
Graph边不在当前技能JSON中；修改容器后需要重新校验并更新Profile摘要。
allowedCombos是开放范围，须与容器连续前缀顺序一致；不一致会拒绝，不能把Graph布局当运行顺序。
视图折叠/缩放/节点位置不属于战斗配置，不应触发战斗版本变化。
不要用“Prepare Phase4A Arena / Prepare Phase4B approved Normal3-5”作为日常更新按钮；它们是历史迁移/测试脚本。

5. 当前限制与回退

行走/奔跑动画缺失及技能动画逻辑帧采样的阶梯感仍为已知表现限制，移动逻辑可用；本轮未调整Animator、动画插值或战斗步长。
Normal6、闪避/闪避攻击、Skill/FinishSkill、武器音效/语音仍未完成正式内容配置。
HitGroup命中特效/音效专用绑定尚不支持，配置非空会拒绝；现有时间轴挥刀VFX已接入。
不承诺所有第三方特效任意Seek；沿用预览安全诊断。编辑器可表达的字段不表示正常宿主已支持全部玩法。
服务器确认两端结果一致，不重算完整战斗，不是反作弊服务器。
跨物理设备/平台、公网、断线恢复、服务端重启持久化不在当前通过证据范围。

配置回退：结束并清理当前match后，在BattleScene相同对象把mode明确改为Legacy，保存并构建两个兼容客户端。
需要当前协议版本1的服务端；不能混用旧二进制或让一端新、一端旧。新模式初始化失败不会自动回退。
Legacy代码保留，但本轮未执行完整Legacy双客户端终局回归，因此只把它列为可配置的待复验回退路径，
不承诺与本轮新模式同等验收覆盖。更可靠的回退基线是保留的已验收构建及匹配版本配置/服务端。
不要git reset整个工作区：Phase5修复与用户既有修改尚未提交。按最终文件清单逐项回退本轮改动。
