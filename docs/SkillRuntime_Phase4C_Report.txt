4. 调用链和固定提交点

BattleManager.LogicUpdate
  -> RoleManager.ConsumeFrame -> PilotBattleSession.Advance
  -> 原输入/移动 -> 同一移动后快照 -> CombatResolver.Resolve
  -> 原 CombatBatch.TryCommit / ICombatStateAdapter.TryApply / 完整 receipt
  -> Runtime.CompleteFrame
  -> DescribeState + 已提交命中 + exits，保存 TerminalState 并 SHA256，构造不可变 TerminalSnapshot
  -> 原宿主退出清理及纯表现回调
  -> 终局停止活动 Cast、缓存动作及运动计划，标记 Player.PilotRoundClosed；不清共享可靠队列/帧历史
  -> PilotResultFlow.Update LockLocal，按未缩放墙钟每0.5秒报告
  -> 服务端 AnalyzeMember（真实 UDP 路由绑定登录成员、IP和独立joinTicket）
  -> RoundAgreement.Report 等双方同作用域/版本/终结帧/结果/摘要
  -> Confirmed 广播同一业务身份
  -> ClientAgreement 暂存/对比本端不可变终局，ApplyCount最多一次
  -> GameManager.GameOver 归档；独立结果面板显示已确认结果
  -> 用户 RequestReturn -> 反复发送 retire -> 服务端身份/结果校验、ClearMatch(expectedBattle)
  -> Retired ACK -> 先停对局调度，再 Dispose 表现/运动/网络订阅，再销毁UDP并清本作用域数据 -> 原清场/MainScene入口。

单个角色死亡、Bindable HP 通知和 Animator/VFX 都不提交胜者。Draw来自完整同帧双方提交。提交失败不会产生 TerminalSnapshot。
早到确认只暂存，必须等本端实际处理对应终结帧并完全相等，不能跳帧或写 HP。
Runtime.CompleteFrame 内部仍使用3C已批准清理语义；外部清理不会重算/覆盖锁定摘要。
等待确认时不停止 NetGlobal/UDP 分发；只有权威战斗冻结。必要 delta/帧数据仍保留。双方都确认后服务端停止生产新帧，历史仍可用于补帧和重试。
终局后 UpdateTerminalPresentation 仅推进有界 VFX/SFX 收尾，不改变逻辑帧、HP、Cast或摘要。
结果会话 DontDestroyOnLoad，订阅和重试不归某个 Player 所有；场景/Player卸载时仍保留已锁定结果。

5. 协议与身份

修改源 Tools/Game.proto；Tools/GeneratePhase4CProtocol.ps1 用现有 protogen 生成两端 C#，服务器子集源另存 Tools/Protocol/PBBattle.proto。并非只手改生成代码。
现有消息编号保留，新增字段使用100起的扩展号；保留服务器原 isRecon=3。现有技能 JSON Schema、Root Motion JSON、3B几何、3C结算算法未改。

TcpEnterBattle：matchId(GUID N)、正 sessionKey、roundId=1、protocolVersion=1、每成员独立 joinTicket。
Ready/Start：作用域、协议版本、authorityMode、规则及配置摘要；Ready含票据。双方都匹配才开局；不支持旧版本则明确拒绝，不静默降级。新版本的 Legacy 模式保留旧战斗/旧GameOver路径；未声称旧二进制无升级兼容。
输入/下行帧/补帧：携带 matchId、roundId，先校验再存储/消费；补帧子包逐一校验。
FinalResult：match/session/round、terminalFrame、显式 Outcome(Winner/Draw)、winnerSlot、stateHash、rules、configHash、protocolVersion。
Winner仅允许槽位1/2；Draw的winnerSlot=0仅作无胜者字段值，结果由显式Draw枚举表达，绝不以0推断Draw。
EntityKey中的session、round、battle槽位、实例代次与CharacterID分开；同角色镜像不混淆身份。
稳定确认ID：matchId + "/1/result"；唯一范围是对局×回合，不含终结帧/请求号。
报告者来自真实服务端路由绑定槽位，不能由请求battleID随意冒用；TCP匹配请求也校验登录连接。
确认要求双方相同规则/配置、同帧、同胜者/Draw、同状态摘要；不允许引用服务端尚未发出的帧。
规则沿用 phase3c-v1/pilot4b-v1（本批未改变战斗数学规则）；结果/作用域握手协议版本为1；配置快照在开局冻结。
Waiting/Confirmed/Conflict/Retired/Rejected分别为业务状态；UDP发送成功/传输收到不是最终业务确认。
重复同报告返回同确认；确认后冲突不覆盖原结果。重复retire不重复退役，ClearMatch检查expectedBattle以免清理新对局。
双方已退役后原服务端对局保留5分钟用于重试，再释放旧路由/历史。路由注销校验实例引用，不注销已经替换的新对局路由。5分钟边界没有本批真实等待测试，见未执行项。

7. 清理表

本地终局：保存不可变最终逻辑摘要；取消未来技能动作，结束活动Cast与运动句柄，冻结权威；保留待确认网络与队列。
等待确认：保留结果、网络收包、补帧、0.5秒业务重试；15秒仅提示，绝不自动判负/判平。
正式离场：先取消旧BattleManager调度；对表现租约幂等Dispose；解绑结果回调；退役UDP代次；此后才清BattleData动作队列、帧历史、游标、scope。
再次入场：新角色/新session，配置的测试初始HP/对称出生位置/朝向、全新Cast序号/HitGroup/硬直/击退/门控；不从死亡动画或UI回调启动权威。
VFX/SFX：Precast非正常退出立即释放；已创建AttackCritical按4B有界寿命收尾；SFX按各自onInterrupt。离场全部释放，不把死亡表现纳入战斗hash。
旧EffectItem：停用或销毁取消自己的timer，销毁解除粒子登记；不全局清所有timer或所有声音。
异步：当前正式消费者为同步Resources加载+独占租约；复用4B旧租约回调不能回收新租约的边界，没有假称已验证不存在的异步加载适配器。
异常场景卸载后的待确认会话保留；进程真正退出则无法继续重试，只记录无伪造结果，未新增跨进程持久化或重连裁决。
