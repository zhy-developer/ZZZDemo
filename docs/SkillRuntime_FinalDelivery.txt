4. 当前实际调用链与唯一权威边界

登录/匹配：
  Assets/Scripts/UI/LoginPanel/LoginUI.cs 登录按钮
  -> FrameSync/Managers/LoginManager.OnClickLogin -> TCP登录/独立进程token
  -> MainUI.Start默认Xingjianya；匹配按钮 -> MatchManager.SendRequestMatchRequest
  -> TcpEnterBattle作用域 -> BattleData.SetScope -> ClearSceneData.LoadScene(BattleScene)
  -> GameManager.Start -> BattleManager.InitData -> RoleManager.InitData
  -> 同对象PilotMatchSettings.Freeze -> PilotBattleProfile.ValidateAndFreeze
  -> 创建真实RoleBase/Player -> PilotBattleSession，角色绑定及初始化HP
  -> SendBattleReady携带mode/rules/config/protocol/ticket；服务端兼容才广播Start。
  -> BattleManager.Message_Battle_Start再次核对，失败不Fallback。

输入和逻辑：
  Player.Update -> PlayerNetworkInput.Capture -> PlayerActionBuffer -> BattleData.UpdateRightOperation
  -> 原UDP输入 -> 服务端整帧 -> BattleManager.LogicUpdate -> RoleManager.ConsumeFrame
  -> PilotBattleSession.Advance：资格/缓存/StartAccepted -> RoleBase.PilotMove
  -> CapturePostMove双方统一快照 -> CombatResolver.Resolve -> CombatBatch.TryCommit
  -> PilotBattleSession.TryApply -> CharacterHealthBase.WritePilotHealth。
初始化HP之外，战斗HP由该完整帧批次写入；通知/血条/旧AnimationEvent不再独立扣血。
  -> Runtime.CompleteFrame及退出清理 -> Present/Player.PilotVisual -> PilotPresentation.Tick。
SkillFrameRuntime管理CastKey、同组记录、单帧结算；SkillMotionTimeline提供已有整数累计差分。
Player.BindDeterministicPilot停止旧FSM推进、Animator根运动和AnimationEvent；RoleBase旧移动路径、
CharacterHealthBase旧伤害入口已有模式门禁；没有同时跑新旧权威链。

终局：
  批量结算Winner/Draw -> 冻结TerminalSnapshot -> PilotResultFlow.LockLocal/重试
  -> 真实服务端RoundAgreement一致性确认 -> 客户端Confirmed只应用一次
  -> 已确认结果面板 -> RequestReturn -> Retired ACK -> 停帧调度/Dispose/清UDP与BattleData
  -> MainScene -> 新匹配、新match/session、重新创建角色与施放/命中/运动/表现状态。
当前“下一局”通过退出重新匹配，不冒充连续回合制。服务端一致性确认不等于服务端重算战斗或反作弊。
