# 玩家动作同步验证

自动回归：

```powershell
dotnet run --project Tests/ActionSync/ActionSync.Tests.csproj
```

测试引用生产队列、状态机和 BindableProperty，不依赖 Unity 或 NuGet 测试框架。覆盖连续输入、重发、确认顺序、重复确认、相同动作保留独立序号、对局清理、重复状态不重新进入、角色停用时状态清空。

## 两客户端验收（需要运行游戏）

1. A 按移动键、松开，B 观察 A 的起跑与停步。反向再测 B。
2. Ctrl 切换走路，停止后重新移动；Shift/右键分别测试前闪、后闪以及前闪结束后冲刺。冲刺时反向移动并停止，确认安比和星见雅都能退出转身状态。
3. 左键普攻、连段、闪避后攻击；A/B 使用同一角色时交替攻击，确认闪避攻击没有修改另一人的普攻配置。
4. E 技能、Q 大招：另一端播放相同动作，远端角色不切换本机镜头、不运行本机大招 Timeline，也不额外触发本机伤害。
5. 连续按闪避/攻击/技能，模拟延迟和重复操作包，确认已发送队列顺序及每个 operationID 只执行一次；闪避可以取消尚未发送的攻击预输入。
6. 暂停一端 Animator 或施加本地顿帧后恢复，确认后续下发攻击仍使用包内连招段数，不因为接收端窗口不同而漏播或改段。
7. 禁用并重新启用角色，确认状态清理和恢复无空引用；确认结束对局后新对局不执行旧动作。

## 协议及边界

沿用 PlayerOperation 字段：rop1=轻攻击，rop2=技能，rop3=大招，rop4=闪避，rop5=走路开关，rop6=重攻击执行入口（当前输入没有独立重攻击绑定）。operationValue1 为输入时的世界朝向（每 3° 一档）；operationValue2 的最低位为是否有移动输入，第 1 位为闪避攻击，右移 2 位为连招段数。

动作资格和段数由拥有者在发送前确定；两端均收到服务器操作帧后执行。发送队列按确切 ID 确认，接收端沿用 battleID+operationID 去重。服务器应原样转发现有字段；仓库不含服务器实现，未做真实服务器互通测试。

这次是动作和动画同步。动画窗口/收尾仍依赖 Animator，未实现确定性战斗、回滚、伤害/敌人同步或服务器动作合法性校验。切人输入原本关闭，保持关闭。
